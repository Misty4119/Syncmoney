# Syncmoney 1.4.0 Beta.1 — Marketplace Listing Copy

Use this copy for the SpigotMC or Modrinth project page. Keep the version marked as a prerelease until a stable 1.4.0 release is made.

## Short description

Vault-compatible Minecraft economy with optional Redis cross-server balances, SQL persistence, transaction safeguards, audit tools, and a Web Admin dashboard.

## Full description

Syncmoney adds a Vault-compatible economy to Paper-compatible Minecraft networks. Choose a local SQLite economy for one server, Redis-backed shared balances, or Redis Pub/Sub with central SQL persistence. VaultUnlocked, PlaceholderAPI, and Web Admin are optional integrations. CMI can remain the economy authority while Syncmoney mirrors currency updates across a Redis-backed network.

Syncmoney manages player balances and its own economy commands. It does not replicate arbitrary permissions or third-party commands, and it does not automatically switch the live economy authority.

### Features

- Local SQLite, Redis shared balances, or Redis plus MySQL, MariaDB, or PostgreSQL.
- Vault and VaultUnlocked interoperability for Syncmoney-managed economy modes.
- CMI sync-only mode that leaves CMI as the currency authority.
- Balance, payment, leaderboard, and administration commands in Syncmoney-managed modes.
- Transaction guards, audit history, optional circuit breaker and player protection.
- Durable quarantine and exact-receipt reconciliation for ambiguous queued payments.
- Optional PlaceholderAPI expansion and embedded Web Admin dashboard.
- Paper, Folia, and Canvas are the 1.4.0 targets for Minecraft 26.2–26.3. Exact tested builds and scenario boundaries are listed in the release readiness record.

### Requirements

- Java 25 or newer for the 1.4.0 prerelease.
- Paper, Folia, or Canvas on Minecraft 26.2–26.3. Plain Spigot is not supported.
- Redis for local_redis, sync, and cmi modes.
- MySQL, MariaDB, or PostgreSQL for sync mode; local mode uses SQLite.
- CMI and CMILib for cmi mode. Vault, VaultUnlocked, and PlaceholderAPI are optional integrations.

### Installation

1. Back up the server's plugin configuration, economy database, and Redis persistence.
2. Install the Syncmoney Beta.1 JAR and dependencies required by the selected economy mode.
3. Start once to create the configuration, then set a unique, non-empty server-name for the node.
4. Select an explicit economy mode and configure only the services it requires.
5. Verify the configured economy authority and storage services before accepting transactions.

For a single server, use local. For Redis without shared SQL, use local_redis. For Redis and central SQL, use sync. Use cmi only when CMI must remain the economy authority. CMI sync-only mode does not register Syncmoney's Vault provider or public economy API, and Syncmoney's economy placeholders are unavailable there.

Before switching an existing network to local_redis or sync, check stored Redis balances against the shared limit of 999999999999999999.99. Syncmoney 1.4.0 does not automatically clamp or migrate existing balances above that limit.
