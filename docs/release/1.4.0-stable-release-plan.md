# Syncmoney 1.4.0 Stable Release Execution Plan

**Goal:** publish the verified stable Core and Web release for Syncmoney 1.4.0.
**Public Core version:** `1.4.0` for the core JAR, PlaceholderAPI expansion, plugin metadata, Core tag, and GitHub release.
**Public Web version:** `1.4.0`, with mirror tag `v1.4.0` and a deterministic source archive.
**Internal candidate:** Beta.3 remains an internal static candidate. Beta.1 artifacts and runtime reports remain historical evidence and do not substitute for stable-version verification.

Updated: 2026-11-07, Asia/Taipei

## Release sequence

1. Set the committed Gradle and Web package metadata to `1.4.0`; synchronize `public/version.json`, the embedded Web distribution, and `WebAdminServer.extractIndividualFiles`. Update the English and Traditional Chinese user, API, architecture, developer, and changelog documents.
2. Build `Syncmoney-1.4.0.jar` and the matching expansion with the release toolchain. Pin their byte lengths and SHA-256 values, along with the acceptance and API consumer artifacts.
3. Run the bounded SYNC acceptance matrix on the exact stable Core JAR: Paper, Folia, and Canvas on Minecraft 26.2 and 26.3. Bind each result to its server JAR hash and bind the matrix to the exact stable Core hash. Do not reuse the Beta.1 matrix.
4. Validate the candidate, runtime, and artifact pins. Push the reviewed updates to PR #41 and wait for every required check on the current PR head.
5. Merge PR #41 using the repository's squash-only method after current checks and review conditions pass. Dispatch `.github/workflows/release.yml` from `main` with version `1.4.0`.
6. The workflow runs release tests, builds and verifies checksums, creates provenance, then creates the unprefixed `1.4.0` tag and a GitHub draft. The `production-release` environment review gates Web mirror synchronization and public publication. Use the configured reviewer gate; do not bypass it.
7. Verify the public Core release and Web mirror: tag targets, stable metadata, expected JARs, `release-manifest.json`, `CHECKSUMS.txt`, attestation, Web source archive, and checksum. Refresh the bilingual readiness record with observed results.

## Required evidence and exceptions

- The stable six-cell matrix must pass against the exact `Syncmoney-1.4.0.jar` SHA-256. The previous Beta.1 matrix is retained as historical evidence only.
- The accepted T21 live scenario, candidate-bound CMI runtime retest, and PAPI cross-pair runtime scenario remain `WAIVED / NOT VERIFIED`. The owner's manual CMI capability test is complete by report; do not request or repeat it. QuickShop UI purchase is optional and unverified.
- Keep all currently open Dependabot PRs open during release preparation. After merge, close only PRs confirmed to be superseded by merged dependency changes.
- The accepted low-severity build-time `deepmerge@4.3.1` advisory remains documented; the Malware-alert inventory remains `UNKNOWN`.
- Stable publication does not claim full coverage beyond the exact server builds and bounded scenarios recorded in the runtime evidence.
